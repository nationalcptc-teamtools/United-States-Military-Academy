# Synthetic team handover

Keep this guide, reviewed source release, exact verification record and useful synthetic examples for the next cohort. Never copy private client evidence/configuration into public handover material. Retired-tool reasons belong in the linked existing decision records; this does not add the excluded transfer/retirement checklist product or practice matrix.

Record a shift note using `note WORKSPACE FILE`:

```json
{
  "kind": "shift-handoff", "actor": "Training operator",
  "scope_changes": "None in this synthetic example",
  "active_jobs": "None", "incidents": "Pending review if any",
  "evidence_location": "Approved private storage reference only",
  "pending_reviews": "Inspect candidate findings and completeness checks",
  "body": "Current workspace revision, release identity and next authorized action"
}
```

To continue: inspect actual state/status and source version, find assigned owner/backup/reviewer, read unresolved decisions and existing-tool runbooks, preserve current/proposed edits, and confirm the next action with the responsible operator. Record stale owner release/transfer explicitly; no new target-claim allocator is provided. Preserve event and user acceptance as separate pending/completed states.

Use known synthetic completed-report examples already supplied with the reporter to learn the import/curation path. There are no new simulator/drill packs or timed exercises. Use manual metrics for retyping, duplicate work, correction/error counts and elapsed time when available; do not invent improvement percentages. Existing tool/script behavior, reviewed releases and license/maintenance holds remain visible in the catalog and prior decisions.

Recover a prior code release by verifying the preserved ZIP manifest/checksum and extracting into a new trusted directory. Preserve working evidence/state before switching versions; unsupported workspace/schema versions fail rather than silently migrating. Review release differences and update the owner/runbook if behavior changes.

For neutral cloud handoff, preview first, inspect selected synthetic content/markings, then explicitly approve export. Transfer is manual and separate; there is no local AI or automatic correction/upload. Keep actual data/client/event/cloud approvals outside this preparation workspace.
