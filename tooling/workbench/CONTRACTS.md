# Workbench contracts and boundaries

Version 1.0.0. Supported layout: `tooling/workbench`, sibling `tooling/farmkit` and `tooling/reporting`. Python 3.10+; only PDF requires the existing optional ReportLab dependency. Read [usage](README.md).

Workspace version 1.0.0 is synthetic-only. `state.json` is the authoritative workflow record, with revision and collections for requests, decisions, authored notes/conflicts, manual plans/runs, review/merge/retest/incident/snapshot records, owners/events and manual metrics. These are local workflow implementation identifiers, not the excluded universal evidence/claim graph. Existing finding/evidence IDs remain those supplied by the report.

Accepted report input remains existing schemas 1.0/1.1/1.2. cptc.tool-run envelopes and arbitrary/native output are unsupported. Source JSON/hash is retained; working claims become candidates until human review. Distinct source/supplied/received hashes are labeled, and neither a hash nor a supplied review string proves truth. Derived snapshots use schema 1.2 for explicit combined restrictions, with the original schema/hash in the manifest.

Appendix API `cptc.appendix/1.0`: the existing reporter's generate function optionally receives paragraph blocks and level-2/3 headings plus explicit inherited markings. At most 200 blocks; paragraph 10,000 characters; heading 180. Kind/type/text checks occur before output. The reporter unions restrictions, validates the derived report and renders one block sequence to Markdown/PDF. Missing required markings fail. Ordinary CLI and report-input schemas remain unchanged. The extended manifest records appendix hash and source schema; it is not a native adapter.

The workbench adds supplied run/incident/retest appendix blocks and inherits every applicable workspace/source restriction, including rejected-source restrictions. There is no automatic declassification, total ranking between PROPIN/PII/FI, sensitivity scanner, client-input enablement or 30-day deletion promise. Custodian/retention/export/deletion references are records only.

Basic limits protect implemented local operations: JSON 2 MB, depth 32; 500 retained event entries with visible truncation; bounded text/target arrays; new destination required for bundles/snapshots/scaffolds; symlink/reparse redirects and protected source/tooling outputs rejected. Source packages contain only enumerated reusable files; private workspaces and reports are not source-package members. Public JSON fixtures are synthetic. A source prefix and its parents must be trusted/quiescent; concurrent hostile file replacement is outside this local integrity model.

Mutations use an exclusive short lock, expected revisions where applicable, and fsync/atomic state replacement. Stale authored edits preserve current/proposed values as conflicts. Lock removal requires an operator to verify no active writer. Snapshot publication stages a complete bundle; a later ledger I/O failure may leave a complete unattached bundle. Inspect its manifest/revision and record the disposition; do not reexecute a target. No multi-file storage system can claim an attachment succeeded when ledger persistence failed.

Manual plan commands never execute their text, perform DNS or allocate target claims. Scope validation uses operator-provided current lists/refs and does not grant permission. The only process supervisor launches a fixed synthetic sleep worker/tree for local lifecycle support. It stops its own child group; cancellation/resume of actual assessment tools remains external and unverified. Typed profiles and operation traffic-budget enforcement are excluded. Existing Linux/Windows runner controls remain separate.

Shared statuses/exit vocabulary: 0 requested local action complete; 1 local/dependency failure; 2 invalid contract/request; 3 pending/conflict/not-ready/mismatch. Successful local action is not event approval. Diagnostic text uses trusted codes, and CLI summaries scrub known secret fields/assignment forms. Raw process output is not logged. Content redaction does not prove sensitive information is absent; actual client inputs remain unsupported.

Cloud handoff contains neutral synthetic JSON/Markdown after explicit human export decision; no API or inference path. No prose drafting, correction engine, native correlation model or automatic finding confirmation is implemented. External system selection/data approval/use occurs outside this application.
